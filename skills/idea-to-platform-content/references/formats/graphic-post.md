# 图文 / 知识卡 / 工具卡

适用于：小红书图文、公众号图文、知识卡、工具卡等以“标题 + 正文 + 图片”呈现的形态。

## 图文结构

```text
标题：承担“结论/命名/对比”之一，一个标题只讲一件事
正文：服务标题的核心观点，段与段推进信息
图片分工：每张图承担一个信息单元，图与图之间是递进或并列关系
```

判断图文的正文是否合格：

- 只看正文能否还原核心观点
- 只看标题能否预判正文方向
- 删掉任何一段，信息是否有损失

## 知识卡

一张卡讲一个知识点。字段：

```text
卡片标题：这个知识点是什么
一句话定义：人话解释，不用术语堆叠
关键边界：容易误解的地方
例子：一个可验证的具体实例
来源：可查证的出处（无出处则标注为个人整理）
```

知识卡不做“知识点罗列”，每张卡必须能独立成立。

## 工具卡

一张卡讲一个工具/方法。字段：

```text
用途：解决什么问题
输入：使用它需要什么
输出：使用后会得到什么
适用场景：什么情况用它，什么情况不用
限制：已知的边界或注意事项
```

## 规则

- 不写死标题字数、图片数量等经验参数；以平台当前实际约束为准
- 图片文字与正文不重复，图片承担正文说不清的结构信息
- 工具卡里的示例默认通用化，用户项目细节不写入（除非明确要求）
- 不写“提升互动”“引发共鸣”这类无法指导决策的话
