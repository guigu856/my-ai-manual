# 线性链路与因果链

## 适用语义

用于表达对象或关系按顺序建立：

- 输入 → 处理 → 输出
- 请求 → 协议 → 系统结果
- 原因 A → 中间变量 → 结果 B
- 第一步完成后才能进入下一步

## 不适用

- 两种方案的并行比较
- 多层父子结构
- 有明确回流的循环机制
- 同一对象发生身份或状态重构

这些情况分别使用 comparison、hierarchy、cycle-feedback 或 state-transformation。

## 对象模型

推荐 2～5 个节点：

- source：起点、输入或原因
- transform：处理中介、机制或协议
- target：结果、输出或终点
- condition：必要条件，可选
- evidence：支撑链路的证据，可选

节点文字只保留角色名和必要判断，不放长段落。

## 空间结构

- 横向：适合横屏和少量节点
- 纵向：适合竖屏和步骤流程
- 折线路径：仅在画幅限制时使用，保持阅读顺序明确

所有节点共用坐标系和统一尺寸规则。连线端点从节点边界和 anchor 计算。

## 推荐状态链

```text
EMPTY
→ SOURCE_REVEALED
→ FIRST_RELATION
→ TRANSFORM_REVEALED
→ SECOND_RELATION
→ TARGET_REVEALED
→ CHAIN_HOLD
```

每个状态都应能独立说明一个中间理解。

## 事件

- reveal：节点首次建立
- connect：关系线或因果箭头形成
- focus：当前讲解节点获得主视觉权重
- hold：完整链路稳定展示
- collapse：链路收束成一句结论，可选

连线不应在终点节点出现前提前暗示完整结果，除非口播已经说出关系。

## 连续性

从前一 Scene 接入时优先保留 source 或已有关系锚点。进入下一 Scene 时可：

- 保留 target 作为下一链路的 source
- 把完整链路降权为背景上下文
- collapse 成一个系统对象

不要整条链路无意义常驻。

## 主要风险

- 视觉顺序和口播因果顺序不一致
- 所有节点一次性出现，失去逐步解释
- 连线穿过节点文字
- 节点过多导致竖屏不可读
- 用线性链错误表达双向或循环关系
- 标签和字幕重复

## Scene 级验收

- 每个新增节点是否带来新的理解
- 连线是否在对应语义 cue 后建立
- 完整链路是否有稳定 hold
- 起点、终点和箭头方向是否准确
- 退出时是否留下正确的连续锚点
