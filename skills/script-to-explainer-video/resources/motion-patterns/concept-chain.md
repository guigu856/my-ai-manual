# 线性概念链路 / 关系重组

## 适用语义

适合表达“能力被调用 → 连接层建立关系 → 系统上下文可用”这类抽象递进关系，也适合“输入 → 处理层 → 输出”或“请求 → 协议 → 结果”等单向建立关系的脚本。

这类动效把关系变化作为主叙事。具体工具、文件、数据库等例子由配音说明，视觉层先保留抽象角色，画面不会被工具清单占满。

## 视觉模型

默认使用 2–4 个语义节点：

- **起点节点**：调用、输入或外部能力，使用操作/输入色
- **中间节点**：协议、连接层或转换层，使用 neutral/ink
- **终点节点**：系统、上下文或结果，使用 teal
- **桥接标签**：只保留短判断，例如“调用只是开始”“连接系统本身”

默认层级：

1. 顶部：短标题，点明当前观点
2. 中部：关系图，表达节点与节点之间的关系
3. 底部：句级字幕，承载配音原文

节点容器可以使用统一的低密度结构框，但它必须绑定图标和模块名，尺寸、间距、位置服从关系网。容器内不放按钮、表格、长列表或重复字幕。

## 空间契约

编码前建立一份布局表：

| 字段 | 约束 |
|---|---|
| x / y | 所有节点共用一个画布坐标系 |
| width / height | 同角色节点统一尺寸；不同角色只按语义需要调整 |
| anchor | 连线端点从节点边缘计算 |
| gap | 节点间距固定，保留安全边距 |
| frame | 外框包住关系图，节点和连线不越界 |

连接线只在节点边缘之间绘制。线的起点、终点、层级和颜色由布局表生成，避免手写坐标造成偏移、穿透或不对称。

## 状态链

推荐状态顺序：

EMPTY → FIRST_NODE → FIRST_LINE → MIDDLE_NODE → SECOND_LINE → THREE_NODE_FLOW → REASSEMBLE

每拍只引入一个新的关系变化：

1. 保留标题和空的关系区域
2. 起点节点出现
3. 起点到中间节点的连线绘制
4. 中间节点出现并稳定
5. 第二条连线绘制
6. 终点节点出现，三节点关系完整
7. 关系图收束、重组或交给下一场景

节点的入场、连线的绘制、标签的出现和退场都读取 cue 帧。动画时间随配音段落变化，不写死绝对秒数。

## 桥接转场

当脚本从“调用能力”推进到“连接系统”时：

1. 保留上一场景的核心节点或关系区域
2. 先出现连接语义，如“我想强调的是”
3. 起点节点沿既有锚点进入
4. 连接线绘制到中间节点
5. 终点节点沿同一关系出现
6. 用一句短判断完成关系收束
7. 再进入下一场景

前后场景共享坐标锚点；新旧元素分拍重组，画面不直接跳成全量终态。

## 文案与字幕

- 标题只保留当前观点，不与底部字幕复述同一句话
- 节点只保留图标、模块名和必要角色说明
- 具体枚举由配音承载，视觉只显示抽象角色
- 字幕逐字跟随 cue，单行、句尾无标点
- 连接词应由配音、字幕和画面桥接共同承担

## 风险清单

- 旋转轨道造成节点偏离统一坐标系
- 连线延伸到节点内部或穿过文字
- 外框、虚线和连线互相穿透
- 终点节点超出关系图安全区
- 节点、标签和字幕同帧堆叠
- 具体工具枚举反客为主
- 标题提前透露下一段结论
- 只检查最终帧，漏掉入场和重组中间帧

## 验收

- 按 0.5 秒抽帧生成接触表
- 重点查看 EMPTY、FIRST_LINE、THREE_NODE_FLOW、REASSEMBLE 四类状态
- 检查节点边界、线端点、对齐、层级、轨迹和入退场
- 检查标题、桥接标签、字幕与 cue 的出现时机
- ffprobe 确认视频帧数、音频时长和最终容器一致
- 发现空间或时序问题后，回到布局表或 cue 数据修正，再重新渲染复核
