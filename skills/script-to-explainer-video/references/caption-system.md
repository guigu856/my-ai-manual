# 字幕系统

字幕的职责是让观众在静音或听觉遗漏时仍能跟上口播，不是把全部画面变成文字版文稿。

## 字幕单位

Caption Cue 按语义短语和阅读节奏切分：

- 保持一个完整短意群
- 不在介词、助词、专有名词中间断开
- 不机械按固定字数切割
- 不强制等同 Spoken Unit

## 默认规则

- 横屏最多 2 行；竖屏优先 1 行，必要时 2 行
- 保持手机小屏可读
- 字幕不得与平台 UI、人物主体或关键图形冲突
- 同一 cue 内避免大段标点；是否去句尾标点由整体字幕风格决定，不设为普遍铁律
- 下一条字幕出现前，上一条必须完整退出或完成替换

## 语义强调

允许：

- 当前关键词变色
- 逐词高亮
- 重点词轻微放大
- 在结论处切换字幕容器或排版层级

不允许：

- 每个字都弹跳
- 所有词使用不同颜色
- 字幕动画比主画面更抢注意
- 为追求卡点破坏语义切分

## 字幕与画面文字分工

- 字幕：口播原意，尽量保持完整
- 标题：当前观点或阶段判断
- 标签：对象、关系和结构名称
- 数据：证据和量化信息

四者不得完整重复。若画面中已经使用大字呈现口播核心句，字幕可降低视觉权重，但仍应保留可读性。

## 时间对齐

- 字幕从 `audio/captions.json` 或 `audio-meta.json` cue 驱动
- 禁止在组件内单独维护另一份字幕时间
- 词级高亮只能使用真实词级 cue；没有可靠词级 cue 时使用短语级高亮
- 字幕出现不应明显早于声音
- 为阅读可适当延后退出，但不得覆盖下一条语义

## 安全区

根据画幅和平台预留：

- 顶部标题安全区
- 底部字幕区
- 竖屏平台右侧交互按钮区
- 底部描述和进度区域

字幕位置由布局系统统一配置，不在各 Scene 内手写不同坐标。

## 验收

逐 cue 检查：

- 文本是否准确
- 切分是否自然
- 是否与声音同步
- 是否被裁切或遮挡
- 是否和画面中的标题、标签重复
- 重点词是否真的值得强调
