# 视觉与动效规则

## 视觉职责

- 画面表达概念、关系和状态变化；叙述性内容由配音和字幕承担。
- 遮住画面文字后，观众仍应能大致理解节点的角色与关系。
- 每个场景只保留完成当前观点所需的元素；复杂关系分阶段建立，不一次堆满。
- 标题是短点题词或模块名，节点文字与配音术语保持一致，标题不提前剧透。

## 资源路由

1. 从脚本提取语义拓扑：线性链路、枚举展开、层级结构、循环反馈、对比映射或状态重组。
2. 读取 `resources/motion-patterns/index.md`。
3. 选择一个主拓扑，再读取对应资源的节点模型、状态链、几何约束、cue 契约和验收清单。
4. 将资源参数写入场景设计，所有时序仍由 `timeline.json` 驱动。
5. 没有归档资源时，记录 `resource_status: pending`，保留局部场景设计，不把一次性方案写成通用资源。

## 状态和空间

每个场景先写：

- 初始状态、关键中间状态和最终状态
- 元素的锚点、轨迹、层级和安全区
- 节点尺寸、间距、连线端点和文字区域
- 与下一场景共享的坐标锚点

动画必须有明确起点和落点。连线从节点边缘计算；局部 SVG 有负坐标时显式处理溢出；进度接近 0 时避免圆头描边鬼影；父级 scale 入场时用外层透明度控制子元素显现。

## 动效语义

- 枚举按配音 cue 逐项出现，节点数量与冻结稿枚举数量一致。
- 关系变化优先于装饰数量；动效需要说明“发生了什么变化”。
- 前后场景通过元素拆分、移动、连接或重组保持连续性。
- 多元素变化拆成多个状态，不在单帧完成全量瞬变。
- 转场起点不能晚于新段落配音开始；新旧信息不能在过渡期互相遮挡。

## 样式默认值

默认深色极简、底色加双语义色、主体居中、移动端可读。用户或平台规范优先于默认样式。品牌 logo 不承担通用概念图标职责，除非用户明确要求。

## 引擎边界

Remotion 和 HyperFrames 都可以作为执行引擎。本 Skill 约束的是时间轴、视觉语义、资源路由和交付契约，不把某个引擎的 API 细节伪装成跨引擎规则。
