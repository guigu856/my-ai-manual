# 修复交接与复审循环

## 1. 修复范围

审查报告把问题分成三类：

- **源文件缺陷**：场景布局、动效逻辑、字幕数据、音频 cue、时间轴或素材需要修复。交给 `../script-to-explainer-video/SKILL.md`。
- **渲染或封装缺陷**：媒体流、编码、字幕烧录、音频合成或导出参数异常。回到渲染工程修复，再生成全新 MP4。
- **审查证据缺口**：缺少冻结文稿、音频、时间轴、播放记录或人审。补齐证据后重新审查，原结论保持开放。

## 2. 严重级处理

| 严重级 | 处理动作 | 交付状态 |
|---|---|---|
| `blocker` | 停止交付，修复根因并整片重渲染 | `fail` |
| `major` | 修复核心内容、时序、字幕或可读性问题，再整片复审 | `fail` |
| `minor` | 记录局部修复项，按用户优先级安排复渲 | `warn` |
| `note` | 作为风格或优化建议，不阻塞当前版本 | `pass` 或 `warn` |

## 3. 标准闭环

1. 把报告中的 finding ID、媒体指纹和源文件路径交给生产 Skill。
2. 生产 Skill 只修复对应源文件、cue 或渲染配置，并保留新版本号。
3. 从同一份 canonical `timeline.json` 整片重渲染；代表帧只用于预检，整片仍需交付复审。
4. 生成新的 MP4 指纹、字幕、报告输入和 `run_id`。
5. 复审原 finding ID 及受影响的相邻区间；必要时重新跑四个维度。
6. 只有新报告明确关闭问题，旧 finding 才能标记为 `resolved`。

## 4. 报告与交付

交接包至少包含：

- 当前 MP4 路径和 SHA-256
- `review-report.json`、Markdown 摘要和采样计划
- 冻结文稿、时间轴、字幕、音频和渲染版本引用
- blocker/major finding 的源文件修复建议
- 需要补齐的 `missing_evidence`
- 下一次复审的范围和通过条件

审查 Skill 只发布审查结论；是否执行修复、是否接受 `warn`、是否发布成片属于用户或生产流程的决策。
