# 发布故障与恢复

## 1. 二维码用户侧不可见

症状：登录进程在后台等待，但用户只收到路径或看不到工具输出。

处理：

1. 复制临时二维码到任务目录稳定路径。
2. 用正式回复中的绝对路径图片直接显示。
3. 标注生成时间和有效期。
4. 用户确认后继续等待原登录进程，不重新启动多个并行登录。

## 2. 网页已登录，CLI 校验仍为 `invalid`

原因：浏览器会话与发布器账号文件是两个状态源。

处理：继续完成发布器自己的 `login`，等待账号文件写入，再执行 `check`。不从网页主页推断 CLI 已登录。

## 3. 中文变成连续问号

根因模式：中文 here-string 经 PowerShell 管道进入原生 Python 进程时发生代码页转换，内容在到达发布 CLI 前已经变成 `?`。

证据特征：提交日志打印的标题已经是 `?AI????`，媒体仍正常。

处理：

- 标题和正文保存为严格 UTF-8 文件。
- 用 Python 读取文件，通过 `subprocess.run([arg1, arg2, ...])` 传参。
- 提交前读取页面输入值，验证 CJK 数量、字符数和关键片段。
- 线上乱码时编辑原笔记，不默认重发。

## 4. CLI 成功但线上内容错误

原因：成功页只证明平台接收写操作。

处理：进入管理页和编辑页回读。核验失败时状态为 `repair-required`，不报告完成。

## 5. 浏览器可执行文件缺失

症状：自动化寻找版本绑定的 Chromium 路径，但文件不存在。

处理：

1. 读取当前依赖版本的运行要求。
2. 检查本机 Chrome 路径并做最小启动测试。
3. 优先通过配置让上游使用现有 Chrome；上游忽略配置时，记录版本与最小兼容补丁，不把一次性补丁写成通用事实。
4. 重新运行账号校验和最小发布测试。

## 6. 标签候选未出现

把失败标签写入发布报告。正文和媒体提交成功不代表全部标签成功。若标签是作品语义必要部分，把标签同时保留在正文 UTF-8 文件中，并在回读时检查。

## 7. 防止重复发布

- 先查发布报告中的 `publish_intent_id`。
- 线上核验失败时修复原作品。
- 只有用户明确要求重发，或平台不支持编辑且用户选择重发时，才创建第二条内容。
