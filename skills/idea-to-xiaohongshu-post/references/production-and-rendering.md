# 视觉生产与渲染

## 输出规格

默认静态图文：

- 画布：1080×1440
- 比例：3:4
- 格式：PNG
- 命名：`xhs-01.png`、`xhs-02.png`……
- 预览：一张按发布顺序排列的 contact sheet

这些是本 Skill 的默认生产规格，不是永久的平台上限。涉及当前平台接口、数量上限或压缩规则时查官方来源。

## 视觉系统

一个作品包使用一个视觉系统：

- Editorial：适合个人观察、故事、观点随笔和慢阅读。
- Swiss：适合比较、方法、AI、工具、流程和结构化判断。
- Evidence-first：适合截图、数据和案例主导的内容。

同一作品内保持：

- 固定安全边距
- 固定标题、正文、页码和页脚锚点
- 一个主锚点色
- 可解释的字体层级
- 有节奏但不随机的版式变化

## 页面形状

7–9 页作品至少使用 4 种页面形状，例如：

- 封面
- A/B 比较
- 流程或状态链
- 警示/误区行
- 证据页
- 大结论页
- 选择/互动页

不要让所有页面都变成“标题 + 三张小卡片”。

## 素材优先级

1. 用户提供的照片、截图、图表和产品素材
2. 可验证来源的真实素材
3. 为特定页面生成的原始视觉素材
4. 功能性排版和语义图形

抽象观点通常可以直接使用第 4 种，不必用通用图库图填空。

### 用户素材

- 保持主体和真实内容，不重绘成虚假界面。
- 截图应足够大，读者能看清关键证据。
- 不拉伸、不随意透视、不裁掉关键文字。

### 网络素材

- 下载到任务目录 `assets/`。
- 在 `assets/SOURCES.md` 记录来源 URL、站点和作者信息（如有）。
- 版权状态不确定时，交付中明确由用户判断。

### 生成素材

- 只生成图片主体或背景，不把中文标题交给图像模型。
- 生成图通常控制在 1–2 页，除非作品本身要求统一插画。
- 画面角色必须服务页面关系，不生成无关的机器人、代码雨和蓝紫色科技背景。

## 渲染路线

### 路线 A：专用社交卡 Skill

当 `guizang-social-card-skill` 或其它专用卡片 Skill 可用时：

1. 使用其种子模板和版式系统。
2. 将本 Skill 的 `work-brief.md` 和 `page-plan.md` 作为内容合同。
3. 渲染完成后返回本 Skill 执行内容一致性与发布门禁。

外部渲染 Skill 只负责视觉执行，不接管观点和事实边界。

### 路线 B：HTML/CSS + 浏览器

1. 在任务目录创建单一 `index.html`。
2. 每页使用固定尺寸根节点。
3. 使用 CSS Grid/Flex 建立稳定布局。
4. 在真实浏览器等待字体和图片加载后逐页截图。
5. 输出 PNG 并验证尺寸。

不要用 Markdown 预览截图、终端截图或办公软件临时截图代替正式渲染。

## 移动端检查

至少检查两种尺度：

- 原始 1080px：检查字形、裁切、锯齿、对齐和素材清晰度。
- 360px 宽缩略图：检查封面、正文最小字号和信息层级。

在缩略图下读不清时：

1. 删掉次要文字。
2. 增加标题或正文尺寸。
3. 扩大证据区域。
4. 更换页面结构。

最后才考虑微调间距，不用极小字号掩盖信息过载。

## 修复纪律

- 内容问题修改 `work-brief.md` 或 `page-plan.md`。
- 文案问题修改卡片源文案和 `post.md`。
- 视觉问题修改 HTML/CSS、模板参数或原始素材。
- 整组重新渲染，重新生成 contact sheet。
- 不直接在 PNG 上覆盖文字或局部修补后冒充源文件已同步。
