# 视频参考拆解 Skill 设计

## 1. 定位

`video-reference-breakdown` 是个人全局 Skill。用户要求“拆解视频”“分析参考片”“看看这个视频怎么剪的”时，Skill 接收本地文件、视频链接或分享文本，自行完成来源解析、下载、媒体探测、抽帧、声音取证、语义分析和 DOCX 报告交付。

Skill 安装到：

```text
C:\Users\32249\.codex\skills\video-reference-breakdown
```

源码位于：

```text
skills/video-reference-breakdown/
```

Skill 不依赖 `video-create` Plugin、MCP Server、知识库或特定项目工作区。

## 2. 输入与输出

### 2.1 输入

Skill 接受以下任一输入：

- 本地视频文件绝对路径；
- HTTP(S) 视频链接；
- 包含视频链接的平台分享文本；
- 当前对话中已经附加的视频文件。

上下文中没有视频来源时，只询问视频文件或链接。来源明确后直接执行，不重复确认文件和链接类型。

### 2.2 输出

每次任务交付：

```text
视频拆解报告.docx
```

报告之外的下载文件、音频、抽帧、联系表、波形和 JSON 证据属于任务工作文件。默认保存在当前工作区的：

```text
output/video-reference-breakdown/<run-id>/
```

工作文件不进入 Skill 包，不提交到 `my-ai-manual` 仓库。

## 3. 总流程

```text
识别本地文件、链接或分享文本
→ 固化来源视频并记录来源信息
→ ffprobe 读取时长、分辨率、帧率、音视频流和时间基准
→ 全片概览抽帧和场景变化候选抽帧
→ 分页生成联系表
→ 提取音轨、波形、响度、能量变化和重要声音变化候选
→ Agent 查看真实画面和声音证据
→ 对复杂或快速变化片段加密抽帧
→ 生成四部分通俗版分析内容
→ 调用宿主文档能力生成 DOCX
→ 完整检查 DOCX 内容和页面
→ 交付报告
```

## 4. 来源处理

### 4.1 本地文件

本地文件直接进入媒体探测。报告记录：

- 原始文件名；
- 文件绝对路径；
- SHA-256；
- 文件大小；
- 媒体时长；
- 视频与音频流信息。

### 4.2 链接和分享文本

来源处理脚本从分享文本中提取 URL，并通过 `yt-dlp` 下载。需要浏览器会话、Cookie 或代理时，读取当前环境已有配置。下载完成后按本地文件合同处理。

来源记录至少包含：

- 用户原始输入；
- 解析后的 URL；
- 平台名称；
- 下载时间；
- 本地视频路径；
- SHA-256。

### 4.3 失败结果

失败信息直接说明：

```text
在哪一步失败
实际错误是什么
缺少什么输入、程序或环境条件
```

禁止把下载失败、浏览器缺失和媒体损坏合并成同一个笼统错误。

## 5. 证据获取

### 5.1 全片画面证据

首次分析同时生成：

- 覆盖全片的等间隔概览帧；
- 场景变化候选帧；
- 带真实时间戳的帧索引；
- 分页联系表。

单张联系表最多使用 `4 × 8` 或 `4 × 10` 网格。长视频分页输出，禁止生成尺寸和耗时无上限的超长联系表。

### 5.2 加密取证

以下情况需要对局部片段加密抽帧：

- 快速切换导致概览帧不足；
- 遮罩、闪白、定格或转场边界不清；
- 声音变化与画面变化的先后关系不清；
- 报告准备写出重要结论，但现有帧证据不足。

加密取证的最大帧间隔为 0.1 秒。只对明确区间加密，不对整条长视频无差别高频抽帧。

### 5.3 声音证据

声音处理生成：

- 可分析音轨；
- 波形图；
- 整体响度和峰值；
- 分段能量变化；
- 明显重音、停顿、声音层进入和退出候选；
- tempo 和 beat 候选。

tempo、beat、场景变化和声音事件在算法阶段统一标记为候选。Agent 查看声音与画面证据后再作语义判断。

## 6. 报告表达规则

### 6.1 面向读者

报告面向没有剪辑和音频工程知识的普通用户。读者无需理解内部数据模型即可阅读完整报告。

### 6.2 每个重要结论的结构

重要结论依次说明：

```text
实际看到或听到了什么
我们的分析判断是什么
判断依据是什么
这个判断有多大把握
```

把握程度只使用：

```text
高 / 中 / 低
```

### 6.3 正文禁用术语

以下内部术语不进入用户正文：

- `MusicSection`；
- `MusicLayer`；
- `AudioEvent`；
- `EnergyCurve`；
- `RhythmUnit`；
- `MainShot`；
- `InShotEvent`；
- `AudioVisualBinding`；
- `EditingSentence`；
- `algorithm_candidate`；
- `agent_inference`。

内部含义映射为：

| 内部含义 | 报告表达 |
| :-- | :-- |
| 一段音乐的结构位置 | 音乐段落 |
| 当前能够分辨的声音组成 | 此时能听到的声音 |
| 对剪辑有意义的声音变化 | 重要声音变化 |
| 音乐随时间的强弱变化 | 音乐强弱变化 |
| 一段完整的视听节奏 | 一段完整的画面和声音变化 |
| 当前承担主要内容的画面 | 画面构成 |
| 画面内部发生的变化和素材处理方式 | 画面处理 |
| 段与段之间的过渡方式 | 与下一段的衔接 |
| 声音事件与画面事件的关系 | 声音和画面的配合 |
| 多个连续镜头构成的复用方法 | 可以重复使用的剪法 |

### 6.4 事实与判断

媒体时长、时间戳、帧、波形、响度和文件哈希属于可验证事实。剪辑意图、观看作用、情绪解释和可复用方法属于分析判断。

报告不得把以下内容写成已知事实：

- 创作者心理动机；
- 无证据支持的软件和插件；
- 压平成片缺少证据支持的图层结构；
- 仍未确认的特效参数；
- 算法候选的节拍和镜头边界。

## 7. 四部分报告合同

报告标题使用：

```text
《视频名称》拆解报告
这条视频好看的原因、它的剪辑方法，以及可以复用到其他视频里的技巧
```

封面后展示来源、时长、画面规格、音乐情况、分析范围和分析时间。

### 7.1 第一部分：这条视频是怎么立起来的

本部分包含：

1. 这是一条什么视频（视频类型和它靠什么成立）；
2. 它大致是怎么做出来的；
3. 它的视觉语言；
4. 节奏与声音的总体方法；
5. 转场与连接的总体原则；
6. 素材与音乐的总体性质；
7. 观众感受如何从开头发展到结尾，附一句话总结。

本部分只保留全片主线，不堆叠逐镜细节。

### 7.2 第二部分：它用了什么素材和音乐

本部分包含：

1. 画面素材盘点：素材类型、景别规律、构图规律、动作方向规律、技术质量；
2. 音乐盘点：整体气质、音乐段落时间线、节拍特征、强弱变化过程；
3. 影响剪辑的重要声音变化。

素材盘点表使用：

| 素材类型 | 大致出现区间 | 景别规律 | 构图特点 | 动作方向 | 技术质量 |
| :-- | :-- | :-- | :-- | :-- | :-- |

音乐段落表使用：

| 时间 | 音乐发生了什么 | 强弱变化 | 画面如何配合 |
| :-- | :-- | :-- | :-- |

声音变化表使用：

| 时间 | 听到了什么变化 | 画面发生了什么 | 带来的感觉 |
| :-- | :-- | :-- | :-- |

### 7.3 第三部分：它怎么一段段剪出来的

本部分分为：

1. 连续覆盖全片的八列时间线；
2. 声音和画面的配合方式。

全片时间线使用：

| 段 | 时间 | 画面构成 | 画面处理 | 附加效果 | 声音与节拍 | 与下一段的衔接 | 把握程度 |
| :-- | :-- | :-- | :-- | :-- | :-- | :-- | :-- |

时间线不得留下未解释的空档。普通段保持易读粒度，复杂段拆成更短区间；复杂段拆细时，“画面处理”列必须覆盖素材使用方式、空间层级与遮挡、进入→保持→退出、运动方式、效果与最终画面效果。“把握程度”列写 高 / 中 / 低，可附证据编号，例如“高（F0012、A003）”。

声音和画面的配合方式依次说明：

1. 声音和画面同时发生；
2. 画面提前行动；
3. 音乐出现后画面再释放；
4. 持续的声音连接前后两个画面；
5. 画面跟随歌词、情绪或声音质感，而不是机械卡点。

### 7.4 第四部分：如果重新做一条，应该学什么

本部分包含：

1. 最值得保留的观看体验；
2. 可以直接复用的方法，按重要程度排序；
3. 不应照搬的原片内容和具体参数；
4. 使用新素材重新创作的执行顺序；
5. 最终检查表。

可复用方法每条包含：

```text
名称
适合什么时候使用
具体怎么剪
能带来什么效果
参考时间
画面依据
声音依据
把握程度
```

方法名称使用“相同方向连接”“先慢后快再停一下”“重拍负责冲击、尾音负责连接”等直接表达。

重新创作只迁移节奏密度、动作关系、声音和画面配合、观看体验及素材选择原则。原片人物、素材身份、绝对时间点、坐标和具体效果参数只留在分析内容中。

## 8. 两种交付模式

### 8.1 独立 Skill

独立 Skill 交付四部分并结束。它不生成知识候选，不调用知识分类、知识检索或知识发布工具。

### 8.2 video-create Plugin

Plugin 报告的前四部分使用同一标题、顺序、表格和表达规则。第四部分之后继续提供：

```text
第五部分：待沉淀知识
```

第五部分保留 Plugin 的阶段、视频类型、知识类型、证据、置信度、去重和用户确认合同。第五部分中的用户可见说明使用中文直述，提交给 MCP 的内部字段保持现有机器合同。

## 11. 验收标准

### 11.1 触发与边界

- “拆解这个视频”“分析这个参考片”“看看这个链接怎么剪的”能触发 Skill；
- “制作一个视频”“审查我生成的成片”“下载视频但不分析”不会误触发；
- 本地路径、链接、分享文本和对话附件都能进入同一流程；
- 独立 Skill 的执行不要求 `video-create` Plugin 存在。

### 11.2 证据

- 输出记录原始来源和本地视频 SHA-256；
- 全片时间线连续覆盖视频；
- 每个重要结论至少引用画面或声音依据；
- 快速变化区间可按最大 0.1 秒间隔补充证据；
- 联系表分页且单页规模有上限；
- 算法候选不会直接写成确定事实。

### 11.3 报告

- DOCX 包含固定的四部分标题并按顺序出现；
- 普通用户不查术语表也能理解每部分结论；
- 用户正文不出现第 6.3 节列出的内部术语；
- 第三部分时间线为八列且连续覆盖全片，复杂段拆细时“画面处理”列覆盖素材使用、空间层级与遮挡、进入→保持→退出、效果与衔接；
- 第四部分给出可操作的连续剪法，而不是抽象评价；
- 第四部分明确区分可迁移方法和原片专属内容；
- DOCX 可打开，所有页面完成渲染检查，无截断、重叠、乱码和破损表格。

### 11.4 Plugin 一致性

- Plugin 和独立 Skill 的前四部分标题、顺序和表达规则一致；
- Plugin 第五部分（待沉淀知识）及知识发布流程保持有效；
- Plugin 在用户确认前不会调用 `knowledge_publish`；
- Context Catalog、Skill 包装和参考学习聚焦测试通过。

### 11.5 安装与仓库

- `quick_validate.py` 通过；
- `evals/evals.json` 可解析；
- 独立 Skill 测试通过；
- 仓库源码与个人全局安装目录内容哈希一致；
- `my-ai-manual` README 收录新 Skill 的职责、目录和使用边界。

## 12. 非目标

- 不把参考片自动复刻成新视频；
- 不生成可执行剪辑工程；
- 不把算法候选伪装为人工确认结果；
- 不建立独立知识库；
- 不复制 `video-create` Plugin 的 MCP、LanceDB 和分析 Job 架构；
- 不在报告正文暴露内部分析对象和机器字段。
