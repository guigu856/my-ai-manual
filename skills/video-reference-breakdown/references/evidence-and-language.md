# 证据与通俗表达

## 事实和判断分开

事实包括：

- 文件来源和 SHA-256；
- 时长、分辨率、帧率和媒体流；
- 某个时间点能够看到的画面；
- 波形、声音强弱和峰值；
- 字幕、遮罩、主体运动和切换实际出现的时间。

判断包括：

- 该处理承担蓄力、冲击或连接作用；
- 某个声音变化推动镜头加快；
- 某套剪法能够迁移到其他素材；
- 观众注意力可能被引导到某处。

正文可以写判断，但必须附实际画面、声音或时间依据，并标明把握程度。

## 重要结论模板

```text
实际看到或听到了什么：
我们的分析判断：
画面依据：
声音依据：
把握程度：高 / 中 / 低
```

## 证据编号

- 概览帧：`F0001` 起；
- 补充帧：`RF00001` 起；
- 重要声音变化：`A001` 起；
- 联系表：使用文件名和页码；
- 时间范围：用户正文使用 `00:04.20–00:06.64` 等易读格式。

## 时间线行内规则

- 复杂段拆细时，“画面处理”列必须覆盖：素材使用方式、空间层级与遮挡、进入→保持→退出、运动方式、效果与最终画面效果。
- “把握程度”列写 高 / 中 / 低，可附证据编号，例如“高（F0012、A003）”。
- 时间线不设“作用”列；作用写在画面处理行内或第四部分可复用方法里。

## 语言改写

| 避免 | 改写 |
| :-- | :-- |
| 建立独立 MusicSection 时间线 | 把音乐按实际变化分成几个段落 |
| MainShot 发生变化 | 画面构成切换到另一个场景 |
| 枚举素材类型 | 说明画面用了什么素材：实拍、动画、图片、UI 界面、文字卡或生成画面 |
| 归纳景别规律 | 说明常用什么景别、景别如何变化 |
| 归纳构图规律 | 说明主体放在画面哪里、靠什么引导视线 |
| 归纳动作方向规律 | 说明主体运动方向如何安排、相邻画面方向是否延续 |
| 归纳素材技术质量 | 说明清晰度、噪点、压缩痕迹和调色特征 |
| InShotEvent 作用于局部图层 | 画面构成没变，但画面处理发生了变化，例如字幕和前景遮挡出现或退出 |
| 建立画面处理说明 | 说明素材怎么叠、怎么动、怎么进怎么出 |
| 建立段间衔接 | 说明这段怎么过渡到下一段 |
| 建立 AudioVisualBinding | 检查声音和画面变化谁先发生、相差多久 |
| 提炼 EditingSentence | 总结一套可以照着重复使用的剪法 |
| 镜头密度上升 | 相同时间内出现了更多镜头切换 |
| 能量释放 | 音乐和画面在这里同时变强 |

## 空泛表达检查

发现以下表述时，补充具体动作和结果：

- 节奏感强；
- 转场自然；
- 画面高级；
- 情绪饱满；
- 增强感染力；
- 提升视觉冲击；
- 增加层次感。

例如把“转场自然”写成：

> 前一个人物和后一个人物都向右移动，切换发生在动作中间，观众会继续追随相同方向，因此背景变化不显得突然。
