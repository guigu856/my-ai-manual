# 观点价值诊断

用于把一个模糊想法、碎碎念或已有文稿，压缩成适合 X/Twitter 传播的核心价值点。

## 1. 先还原原意

先回答六个问题：

1. 用户在讨论什么具体对象？
2. 用户最想表达的判断是什么？
3. 这个判断针对什么真实问题、摩擦或误区？
4. 用户给出了什么经验、例子、机制或理由？
5. 哪些内容只是情绪或语气，不是事实主张？
6. 哪些地方存在跳跃、过度归纳或暂时无法确认？

输出核心主张时，必须保持用户原意。不能把“我发现 X 经常发生”改成“所有人都在 X”，不能把个人经验直接写成普遍规律。

## 2. 价值判断

一个观点至少命中以下一项，才值得单独做成推文：

- **非显而易见**：读者看完获得一个之前没有明确意识到的判断
- **纠偏**：指出常见做法中的误区、假进步或错误激励
- **痛点**：准确说中某类人反复遇到但不容易描述的问题
- **机制**：解释形成原因，而不只给结论
- **判断规则**：给出可直接用于下一次决策的标准
- **边界**：指出某个正确原则在什么情况下不成立
- **方法**：提供可执行、可验证的下一步动作

“正确”本身不等于“有发布价值”。

例如：

- “做事要专注”是常识。
- “不停找 Skills 会制造一种假进步感，让寻找工具替代真实任务”包含更具体的对象、失败模式和判断价值。

## 3. 隐藏价值挖掘

当原始观点太大众化时，只从用户已有表达中寻找下面这些结构：

### 假进步

表面上像在推进，实际没有缩短目标距离。

常见形式：

```text
收藏 / 学习 / 配置 / 研究越来越多
→ 真实任务没有产生结果
→ 手段开始替代目标
```

### 隐藏成本

某个看似有帮助的行为，实际增加切换成本、决策成本或启动阻力。

### 错误激励

人会因为某个行为“看起来像工作”而持续做它，即使它没有带来验证结果。

### 反馈闭环

把抽象建议转成：

```text
行动 → 结果 → 判断偏差 → 修改 → 再行动
```

如果用户的真正价值来自闭环，不要只保留“多试几次”这种表面结论。

### 边界条件

找出用户原话里隐含的“什么时候有效 / 什么时候无效”。

例如“要求越具体越好”可能需要被修正为：

- 结果和验收标准要具体
- 实现过程不一定需要提前规定死

### 决策规则

把经验转成下一次可以直接使用的判断：

```text
如果现有工具已经能跑完一轮验证，就先跑；不要因为可能存在更优工具而中断任务。
```

## 4. 角度选择

一次发布只选一个主角度。

优先顺序：

1. 最具体
2. 最能命中真实摩擦
3. 最有信息增量
4. 最能被解释或验证
5. 最适合当前输入长度与发布格式

不要把所有可用角度都塞进主帖。其余角度可以成为回复或后续独立推文。

## 5. 观点强度

根据证据状态控制语气：

| 状态 | 允许写法 |
|---|---|
| 已确认事实 | 直接陈述，并保留必要条件 |
| 用户个人经验 | 使用“我发现 / 对我来说 / 我的经验是”等个人边界 |
| 合理推导 | 使用“更像是 / 可能意味着 / 我更倾向于”等适当强度 |
| 无法确认 | 删除、核验，或明确写成未知 |

不能为了提高传播力把低强度证据改成高强度断言。

## 6. 失败模式

直接拒绝以下处理方式：

- 把具体洞察抽象成“坚持、专注、执行力很重要”
- 为了反常识，凭空制造一个对立面
- 用“绝大多数人”“99% 的人”“真正高手”制造虚假群体共识
- 把用户没有说过的商业、社会或人生意义补进去
- 用更强烈的措辞掩盖论证不足
- 把多个不同观点拼成一句看似厉害但无法验证的金句

## 7. 最小价值单元

一条有价值的推文通常至少包含以下两项：

- 一个明确判断
- 一个机制、边界、例子或行动含义

只有态度，没有信息增量时，不足以单独成帖。
