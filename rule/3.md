# 项目结构规范 (Project Structure Guidelines)

为了确保项目的长期可维护性、高内聚和低耦合，本工程遵循以下项目结构与代码组织规范：

## 1. 职责驱动划分 (Responsibility-Driven Partitioning)

针对基础目录下的 `.java` 文件，必须基于 **业务领域（Domain）** 和 **单一职责原则（SRP）** 进行拆分。

- **禁止创建"上帝类（God Class）"**：避免在单一类中堆积过多互不相关的逻辑。
- **物理拆分标准**：
  - 如果一个类的逻辑超出了其命名定义的范畴，必须进行拆分。
  - 如果代码行数过多导致阅读和维护困难，应按功能逻辑进行物理拆分，确保类文件的纯净度。

## 2. 维度与包管理 (Package & File Assessment)

在编写业务代码前，必须先评估其业务维度。

- **按功能模块隔离**：如果涉及新的子业务或功能模块，应果断新建 `package` 或对应的类文件。
- **职责隔离**：通过合理的包路径来隔离不同职责的逻辑，禁止将新逻辑强行塞入现有的、不相关的包中。
- **预判性设计**：在开发初期即考虑包结构的扩展性，避免后期大规模重构。
