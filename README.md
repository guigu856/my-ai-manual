# My AI Manual

本仓库用于存放 AI 辅助编程相关的配置文件，包括编码规范 (Rules) 和技能定义 (Skills) 等。这些文件用于指导 AI 助手在代码生成、审查和重构过程中遵循统一的标准和最佳实践。

---

## 目录结构

```
my-ai-manual/
├── rule/          # 编码规范文件
│   ├── 1.md       # 基础行为准则
│   ├── 2.md       # 命名与文档规范
│   ├── 3.md       # 项目结构规范
│   └── 4.md       # 代码逻辑与质量规范
├── skills/        # AI 技能定义 (待补充)
└── README.md      # 本文件
```

---

## 规范文件说明

### rule/1.md — 基础行为准则

**核心思想**：编码前思考，保持简单，精准修改，目标导向。

| 原则 | 要点 |
|------|------|
| Think Before Coding | 明确假设、表面权衡、有疑问先问 |
| Simplicity First | 最小代码解决问题，不预支功能，不过度设计 |
| Surgical Changes | 只改必要代码，不重构无关部分，清理自己产生的废弃代码 |
| Goal-Driven Execution | 定义可验证的成功标准，测试先行 |

---

### rule/2.md — 命名与文档规范

**核心思想**：命名望文生义，注释聚焦过程。

- **极简语义化命名**：使用行业通用、无歧义的动名词组合（如 `saveOrder`, `isPaid`），禁止生僻词
- **过程导向注释**：注释应解释复杂逻辑和决策背景，禁止废话注释、修改历史、重复命名信息

---

### rule/3.md — 项目结构规范

**核心思想**：职责驱动，高内聚低耦合。

- **职责驱动划分**：按业务领域 (Domain) 和单一职责原则 (SRP) 拆分，禁止"上帝类"
- **维度与包管理**：新子业务应新建 package，通过包路径隔离职责，预判扩展性

---

### rule/4.md — 代码逻辑与质量规范

**核心思想**：小而美，零容忍，显式表达。

- **函数粒度约束**：方法过长/过深时重构，主流程如"目录"般清晰，细节隐藏在私有辅助方法中
- **魔法值零容忍**：业务含义的常量必须定义为 Enum 或静态常量，保持自解释能力
- **避免全限定符**：使用 import 引入类，仅在类名冲突时才允许使用全限定名

## 使用方法

1. 将本仓库作为 Windsurf / Cursor / GitHub Copilot 等 AI 编程助手的上下文参考
2. 在 Rules/Skills 配置中引入对应文件路径
3. 根据项目实际情况，在 `skills/` 目录中补充项目特定的技能定义

---

## 贡献与更新

- 规范文件采用 `alwaysApply: true` 标记，表示全局生效
- 新增规范时按序号递增命名（如 `5.md`）
- 项目特定技能定义存放于 `skills/` 目录，以功能命名（如 `api-integration.md`）
