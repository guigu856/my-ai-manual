# 脚本 → 概念动效视频生产线

## 总原则

**先声音，后画面。** 配音实际时长是全片唯一时间基准（音频主时钟）：视频帧号由音频时间轴推导，永远不反过来。

三条铁律：

1. **音频驱动一切**：所有动效节拍、字幕帧、转场点都从主时间轴读取，禁止凭感觉写死秒数。
2. **中央构图、无常驻**：主体概念居中呈现；不设全片常驻元素、不拉跨场长线。元素只在语义需要时作为场景内元素出现，该退就退。
3. **不逐帧自检不交付**：全量接触表逐帧审查是强制步骤，不得用关键帧抽检代替，不得等用户发现问题。

用户只给脚本时，以下默认值直接执行、不要反问：1400×1000（7:5）@30fps 横屏；深色极简技术风；中文女声（自然、冷静、有判断力）；响度 -16 LUFS；H.264+AAC；最终必须交付可观看成片，不是方案或分镜建议。

## 流程（7 步，顺序不可换）

### 步骤 1：冻结文稿 → 分段 + 文案强化

- 文稿按语义切 8–14 段，每段 1–3 句，写入 `segments.json`：`id / chapter / title / text`。
- `title` 是画面唯一保留的核心标题，精炼到 2–6 字（点题词或模块名，不是句子）。
- 分段时同步做文案强化：
  - 抽象论断后必须跟「例如」+ 具体业务场景，形成「判断→例证」对仗（如：搜索→实时查询天气、数据库→检索业务数据、控制软件→操作外部应用功能），避免直接抛概念。
  - 段落按「观点→展开→收束」组织，保持口语化叙述流，不堆句号。
- 文稿一旦冻结，后续字幕与画面内容以冻结稿为准，不得再改写。

### 步骤 2：配音合成与实测时长

- edge-tts 逐段合成，同时收集 `SentenceBoundary`（offset/duration 为 100ns 单位，÷1e7 得秒）作为句级 cue。注意 edge-tts 7.2.x **没有 WordBoundary**。
- 声线：`zh-CN-XiaoxiaoNeural`，`rate=-4%`、`pitch=-5Hz`（冷静中性偏低）。Xiaorui/Xiaohan 等新声线在该版本会 `NoAudioReceived`，不要尝试。
- 每段时长以 **ffprobe 实测**为准（不用 TTS 报告的 duration）。段间留 0.35–0.45s 间隔。
- 拼接前全部转 48kHz mono wav（**mp3 与 wav 混用 concat 会静默丢段**），首尾静音也做成 wav 串入。
- 拼接后 `loudnorm=I=-16:TP=-1.5:LRA=11` 生成 `vo_final.wav`。
- 禁止用正弦波、白噪声、低频脉冲、持续嗡鸣制造"科技感"背景声；默认不加 BGM，纯人声。

### 步骤 3：试听验收（信号级，通过才继续）

- 每段时长 ≈ 字数 / 4.6，偏差超 ±40% 判为 TTS 异常，重合成。
- `volumedetect`：max_volume > -8dB 疑削波。
- `silencedetect`：无 >2s 异常静音（段间 0.4s 不算）。
- 总时长核对：`ffprobe vo_final.wav` ≈ 时间轴总帧数 / fps。
- 这一步不过就等于在错误的时间轴上盖房子，必须先过。

### 步骤 4：主时间轴 timeline.json

- 内容：画布参数、每段起止帧、句级 cue 帧号（`Math.round(sec * fps)`）。
- 之后 Remotion 动效、字幕、QC 全部以此文件为唯一时钟来源。

### 步骤 5：Remotion 动效

**先设计后编码**：每个场景先写清关键状态链、完整运动路径、布局网格、安全区、标题区、字幕区、模块尺寸、元素间距、锚点位置，再写代码。不是先做静态画面再加动画，而是从一开始就设计成连续、有语义的动态系统。

结构与节拍：

- 单 Composition，章节用 `<Sequence>` 交叠约 16 帧溶解；跨章连续元素在两章同一坐标渲染同一姿态。
- 动效节拍 = cue 帧号，从 timeline.json 读取。章内用相对节拍常量：某段文案变长时，只平移受影响章节，其余章内相对节拍不变。
- tsconfig 必须有 `"resolveJsonModule": true`。

构图与尺寸：

- 主体居中；每章独立场景，切换时旧元素该退就退、该清就清，不累积。
- 元素尺寸"偏大不怕，偏小不行"：节点、字体按移动端可读性设（标题约 42px、字幕约 36px、节点半径 50px 起），画布上按网页直觉设的大小一定太小。
- 画面空旷不靠加装饰解决，靠元素间有机组合与布局强化主题；复杂场景分阶段呈现，不全量堆叠。

视觉红线（全部为硬性要求）：

- 禁 PPT 感、卡片轮播、软件 UI 演示、大段文字朗读。
- 概念元素用图标、形状、节点、路径、容器表达；**禁"文字+矩形外边框"卡片形态，圆角描边矩形也算**（含 bullet 列表容器、按钮态胶囊）。"包装/包含"语义用细括号、包裹线、容器轮廓表达。
- 画面文字只留：核心标题、短判断、必要模块名。删除一切栏目名、状态信息、编号、版本、数据、英文小字、伪 UI。
- 禁止副文本小字复读字幕内容——语义叙述由字幕承担，节点只留图标+模块名。
- 模块名与配音用词逐字对应（配音说"操作文件"，模块名不能写"文件"）。
- 不用品牌 logo 充当通用概念图标（商标与误导风险），用中性通用图形。
- 深色底（约 #0B0E13）+ 双语义色（如 teal=主体侧、amber=上下文侧），不引入第三色除非语义必须；新色介入要收敛、有过渡。
- 遮住文字后，观众仍应能大致看懂元素功能与关系。

标题纪律：

- 标题只在配音说到对应内容时出现——**不提前剧透结论，不滞后，也不挂超过所属段落**（进入下一语义段前淡出或降级）。
- 标题与字幕不得同屏同义复读：字幕承担叙述整句，标题只留点题词/模块名。
- 标题与其所属图形绑定为一组，同进同出。

动效语义与枚举场景：

- 动效必须承担概念解释：复杂度来自元素关系的变化，不是元素数量。
- 枚举逐项跟随配音节奏出现（每项约 0.8s），"听到哪个、看到哪个"；禁止配音还没念完就全量铺完，也禁止逐项间隔不均。
- 枚举节点数量 = 文稿枚举数量，一个不多；配音未念出的概念不得混入同级枚举。
- 枚举所有标注必须在该段配音结束前全部到位，不得缺项。
- 长枚举优先串行"出现一个、讲完淡出一个"，不四列同屏堆满。
- 前后场景保持视觉连续性：原有元素通过拆分、移动、连接、重组推动观点发展。

转场规则：

- 场景切换必须走元素重组（前场元素收缩/变形/飞出成为后场一部分），**禁止硬切**（全部元素同帧瞬变/瞬消）。
- 多元素同时变化拆成 2–3 拍完成，不同帧突变。
- 元素消失必须有过渡（收缩/淡出 ≥0.5s），禁止一帧之内从"满屏信息"变空白。
- 转场起点 ≤ 配音新段落起点，不允许新段开讲 1s 后还停在上一段画面。
- 先收旧元素再出新元素，过渡帧不允许新旧信息打架。
- 结尾收束帧清空所有图形与字幕到纯背景；全片同一术语用词统一（如一直说"脚本"不得末帧变"模板"）。

两条语义线经过同一区域时共用同一直线：前者淡出时后者绘入，读作"状态转化"而非两条线打架。

组件安全编码（实际踩坑，逐条照做）：

- 进度线组件 `p <= 0.005` 时 `return null`，否则圆头描边会渲染成 1px 孤点鬼影。
- 带 scale 入场的容器：父级 scale=0 时子元素 opacity 仍为 1 会提前显形，必须整体包一层淡入透明度。
- 淡出用 `* fo(...)`（1→0），不要写 `(1 - fo(...))`（前期恒 0 导致元素不显示）。
- SVG 局部连线加 `style={{overflow:'visible'}}`，负坐标才不会被裁。

### 步骤 6：抽检 → 全渲 → 合成

- 先 `remotion still` 渲每章 2–3 个代表帧确认构图与文字尺寸（仅为快速验证，不代替步骤 7）。
- 全片渲染后合成：`ffmpeg -i video.mp4 -i vo_final.wav -map 0:v -map 1:a -c:v copy -c:a aac -shortest out.mp4`。
- Remotion npx 在部分 Windows 机器 exit code 恒为 1 但产物正常：以产物存在且可播放为准，still 偶发失败直接重试。
- ffprobe 核对：视频帧数 = 时间轴总帧数；音频时长 ≈ 视频时长（±0.1s）。

### 步骤 7：逐帧全量自检（强制）→ 修复循环 → 交付

- `ffmpeg -i out.mp4 -vf "fps=1/2,scale=700:500,tile=4x4:margin=8:padding=8" -frames:v N sheet_%d.png`：每 2s 抽 1 帧拼 4×4 接触表，逐张看完。
- 检查项：错位/越界/偏线、文字重叠/裁切、鬼影、子元素提前显形、连线打架、交叠期元素叠加、元素占比、字幕单行与截断、标题出现时机。
- 发现问题 → 修复 → 复渲 → 复检，循环到全量通过才算交付。
- 交付时直接给出成片文件，不把"自己检查"的责任推给用户。

## 字幕规范（8 条硬规则）

1. 每条字幕**只允许一行**，不得出现两行。
2. **句末无标点**：句号、问号、感叹号一律去掉。
3. **无断层**：cue 连续覆盖全片，段间间隔也要有字幕覆盖；转场时字幕消失与新场景出现同帧完成，不留真空。
4. **长度控制**：单条 ≤20 字，超出在逗号/顿号处切分到下一条。
5. **句子完整**：一个完整意群不得截断到两条；双音节词不得跨条拆开（如"项目状态"必须完整落在同一行）。
6. **字幕 = 配音逐字原文**：不得改写、不得加词（配音没有的"例如，"不能凭空出现在字幕），枚举句就是配音原文的枚举。
7. **时序**：字幕出现帧 = 句级 cue 帧 ±1 帧；字幕跟随配音精确切换，念完后停留不超过 1.5s。
8. 全片标点统一全角；导出 SRT 用 `utf-8-sig`（剪映兼容）。字幕组件留 maxWidth 兜底（约 1180px），顿号长枚举句不会被逗号切分逻辑捕获。

## 配音替换与声音克隆立场

- 用户想要特定真人音色（如剪映/抖音爆款声线）：该类音色无公开 API，**走剪映 SRT round-trip**——从 timeline 导出句级 SRT（utf-8-sig）→ 用户在剪映导入选音色朗读 → 导出音频发回 → loudnorm 后重混；若新配音各句时长变化，以新音频重建 timeline 并重渲染（音频主时钟架构天然支持）。
- **未授权的真人声音克隆必须明确拒绝**（伦理红线），并给出上述合法替代路径。

## 决策记录（为什么这样做，执行时不要动摇）

- 为什么自建 Remotion 流程而不是现成管线：观点类片视觉要求高度定制（状态链/锚点/重组转场），程序化渲染才有逐帧控制力。
- 为什么音频主时钟：配音自然语速不可预知，先画面后配音必然导致动效与讲解脱节；先配音则一切节拍有据可依。
- 为什么中央构图、无常驻元素：常驻标志+跨场长线被用户强烈反感（"一直挂在那里""时不时来一条线"），且小屏上持续抢占视觉。
- 为什么逐帧自检强制：曾交付带错位/重叠/偏线的成片被用户斥责"做完不自己检查"；接触表全量审查成本很低，漏检代价很高。

├── audio/             # segNN.wav → vo_raw.wav → vo_final.wav
